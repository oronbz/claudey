# Domain docs

This project uses a single-context layout.

Before exploring or changing the project, read root `CONTEXT.md` and relevant decisions in `docs/adr/`. If absent, proceed silently; domain-modeling creates these documents when needed.

Use the glossary's canonical terms. Surface conflicts with accepted ADRs explicitly; respect superseding decisions.

Keep `CONTEXT.md` a glossary. Record architectural decisions in ADRs and feature requirements in the issue tracker.
